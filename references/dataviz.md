# 图表用色

原先 `SKILL.md` 一句「数据可视化不在范围内，因为分类色需要等权，与三色不等权冲突」
——这个理由只对**分类色**成立，对序列色和图表中性件都不成立。这里把范围收回来。

`handoff.json` 的 `chart` 段就是交接口。

## 在范围内

### 序列色（sequential）

同族明度阶，本身就是不等权的，与「梅子青瓷同族三色靠明度分层」是同一套逻辑。

必须走 **LCH 色相窗口 + L\* 等距**，不能用 `--family`：青族按字面只有 9 条，筛不出五档。

实测四条可用梯：

| 色向 | 色相窗口 | 五档（由浅到深） |
| --- | --- | --- |
| 蓝青 | H 200–280 | 清水蓝 → 碧青 → 鸢尾蓝 → 靛青 → 鷃蓝 → 苍蓝 |
| 红橙 | H 20–50 | 洋水仙红 → 瓜瓤红 → 胭脂红 → 淡土黄 → 可可棕 → 金鱼紫 |
| 黄 | H 70–100 | 雅梨黄 → 土黄 → 草灰绿 → 潭水绿 → 蟹壳绿 |
| 绿 | H 120–180 | 嘉陵水绿 → 田园绿 → 孔雀绿 → 飞泉绿 → 荷叶绿 → 油绿 |

**明度单调是硬要求**，逐阶校验（`selftest.test_handoff` 有断言）。

### 双向色（diverging）

两臂各自 sequential，中点取近中性纸色（米色 `#f9e9cd` 或 月影白）。

禁 红↔紫（按青间紫同类处理）。用 红↔蓝、红↔青、黄↔蓝。

### 图表中性件

| 件 | 取 | 要求 |
| --- | --- | --- |
| 轴线、刻度字 | `tokens.text` / `muted` | ≥4.5:1 |
| 网格线 | `tokens.border` | 可以弱 |
| 零线、参考线 | `tokens.border_strong` | ≥3:1 |

库内**没有真中性灰**（a\*≈b\*≈0 的色不存在），所以中性件必须与底同冷暖，否则网格发脏。
这正是 `dataviz` 那边 `references/palette.md` 里品牌中性占位色的替换落点。

## 部分收回，带硬上限

### 分类色（categorical）：上限 5

四条闸门同时成立才收：

1. 两两 ΔE2000 ≥ 25
2. 三种色盲（protanopia / deuteranopia / tritanopia）模拟后 ΔE ≥ 12
3. 排除青×紫配对
4. 对纸底 ≥ 3:1

**选法很影响结果，闸门本身不放宽。** 单趟贪心会按起点聚堆：按彩度降序只出 3 类
（银朱/玫瑰紫/筍皮棕，全在红紫区），按色相升序出 4 类但仍然扎在红紫。
所以改成多起点小搜索，取「类别数最多、两两最小 ΔE 最大」的那组，仍然是确定性的。

实测（`handoff.categorical`，全部四条闸门都跑）：

| 底 | 类数 | 两两最小 ΔE | 结果 |
| --- | --- | --- | --- |
| 鱼肚白 | 5 | 28.4 | 银朱 / 胆矾蓝 / 鷃蓝 / 棕榈绿 / 葡萄酒红 |
| 雪白 | 5 | 32.3 | 胭脂红 / 翠蓝 / 鷃蓝 / 暗海水绿 / 葡萄酒红 |
| 燕颔蓝（深底） | 5 | 27.2 | 佛手黄 / 柏林蓝 / 碧青 / 吊钟花红 / 孔雀绿 |

5 是上限，不是目标。到不了 5 就用到几算几，`max_safe_n` 会如实报出来。

## 拒绝清单（写死四条）

1. **类别 ≥6** —— 超过色盲安全上限。替代：小倍数（small multiples）、直接标注、
   明度阶 + 形状/纹样区分。这是**设计层改动**，必须向用户说明并取得同意，不能静默换。
2. **用户点名 rainbow / jet / 彩虹** —— 明度非单调，序列语义会失真。
3. **要把三色直接当图表填充** —— 标点是标点不是面，铺成 8 个扇区即违反不等权。
4. **要用 success/warning/error/info 当分类色** —— 它们是徽章内部色。
   实测藤黄 `#ffd111` 对白 1.46:1、对乳白 1.32:1，根本读不出。

## 两条硬声明

- **序列色不占标点额度。** 它是第四组令牌，不要因为「标点用完了」就把 error 改成品牌色。
- **不要把序列里的色回填成品牌色。**

## 仍不在范围

Ant Design 的 10 阶交互链、Material 3 的 tone palette。要接这类系统，
把 `accent` 当种子色交给它们自己的算法。
