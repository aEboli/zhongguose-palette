本文件给技能调用者看：为什么这样分角色、怎么混色、怎么判断一套三色「好看」。

## 1. 三色层级是什么

室内设计与穿搭里通行的做法：一个主导的场（底）、一组承托的结构、几处最小面积的点缀（标点/动作）。

核心是**不等权**——三者的视觉分量必须依次递减，而不是均分画布。一张图需要一个场、一组支撑、几处标点。同一角色可以是一族相近色，不必是单一 hex。

具体铺色面积不是固定数字，由感知能量反推（见第 3 节）。同一套三色在插画和界面里的实际占比会不同。

中国传统气质常常比通用配色更偏向大面留白：大面纸 + 墨 + 一点朱。留白算进主场，不是「没有颜色」，不要为了填满三色块把点缀放大。

## 2. 按响度分角色

三枚 hex 里：

- **主场**：最静、最近中、明度最靠两端（宣纸或墨底）。
- **结构**：中等对比、中等彩度，成块出现但不抢点击。
- **点缀**：彩度最高、与场对比最强，通常更暖。品牌主色若很响，落在点缀而不是主场。

视觉重量随彩度、明度对比、暖色前突、位置、空白包裹而上升（Helmholtz–Kohlrausch：同亮度下高饱和更亮）。把最响的色铺成主场会让页面变成广告布。

中国传统色的读法：**素地为局、正色为骨、一点朱/金为眼**。

| 角色 | 典型取色 |
| --- | --- |
| 主场 | 乳白、月白、汉白玉、鱼肚白、粉白、燕颔蓝、豆沙 |
| 结构 | 群青、战舰灰、瓦松绿、茶褐、花青、长石灰 |
| 点缀 | 银朱、朱红、苋菜红、姜黄、甘草黄、孔雀绿 |

文字和图标是 on-token，不是饼图的第四切，不要把「黑字」算进结构色。

## 3. 面积 ≠ 视觉重量

感知能量 E ≈ Area × Intensity。Intensity 由彩度、与场的明度差、暖度共同决定。一小块高彩朱红可以等于一大片柔和点缀。

脚本 `visual_areas()` 按这个关系反推建议铺色面积，点缀被夹在一个很小的区间里。交付时用 `pixel_pct`，不要把点缀铺成整条色带。

眩眼测试：眯到只能看见大色块时，应看到一大块场、一个结构带、一两个亮点。三块一样亮，说明点缀用多了。

UI 落位：

- 主场 → `html/body`、主栏背景
- 结构 → aside、header、次要卡
- 点缀 → `.btn-primary`、`.active`、badge、focus ring
- border 用结构色的低彩近亲或场的加深，不用点缀色描所有框

海报：60=纸地/天空，30=主体色块，10=印章、题名、一道朱线。
服装：60=主面料，30=缘饰/里衬，10=盘扣/绣/佩。
空间：60=墙面（必须低彩），30=家具，10=摆件或一扇门。

## 4. 色相和谐与荆浩口诀

西方色轮（Itten）仍然有用，但中国色名不是均匀分布在色轮上的。先看关系，再看角度：

| 关系 | 色相夹角 | 用法 |
| --- | --- | --- |
| 同族 / 单色相 | 0–25° | 最稳，靠明度分层（梅子青瓷） |
| 邻近 | 25–60° | 雅致默认 |
| 分裂互补 / 三角 | 120–150° | 点缀跳出来，场和结构仍要安静 |
| 互补 | 150–180° | 只让点缀去互补，主辅互补太冲 |

五代荆浩口诀是现存最凝练的中国配色规则：

> 红间黄秋叶坠，红间绿花簇簇，青间紫不如死，粉笼黄胜增光。

- **红间黄**：秋叶，故宫琉璃、秋香素绢。暖色同向，稳。
- **红间绿**：花簇簇。年画、门神可以，而且必须一大一小；雅、清冷里要减分。
- **青间紫不如死**：蓝绿配紫是点名的死局。数码蓝配洋红按同一条处理。脚本对青×紫乘 0.45。
- **粉笼黄胜增光**：米白、粉白、牙色优于纯白。纯 `#ffffff` 在中国色里显冷、显假。

冷暖：主辅同向（或都中性）最稳。点缀可以反转。浓烈 / 市井 / 艳允许主辅冷暖对撞——敦煌土红墙配石青就是故意的。

底调：同一方案里的「白」必须统一冷暖偏移。朱红主题下用月白（偏绿蓝）会脏，改用汉白玉、乳白、粉白。库内没有真正的中性灰（a\*≈b\*≈0），设计前提就是「有温度的中性」。

## 5. 混色：LCH 弧线 vs Lab 直线

禁止在 sRGB 或 HSL 里平均两个颜色。HSL 的 L 不是感知明度，黄和蓝在 HSL L=50 时观感差一倍。

| 色相夹角 | 走哪条路 | 原因 |
| --- | --- | --- |
| ≤150°（同族、邻近） | LCH 最短弧，可略降彩度 | 保住色相，得到「调出来的」中间色 |
| >150°（补色） | Lab 直线 | 中点自然经过近中性。走 LCH 弧会经过第三种色相：朱红×石青混成紫，那不是这两色调出来的 |

`colorkit.bridge()` 按夹角自动选路。补第三个色时：先在连续空间里求出理想点，再 `Catalog.snap()` 吸附到 526 色最近邻。输出仍然是库内色名。

越域时保明度、保色相、二分降彩度（`fit_gamut`），不要直接裁 RGB 通道——硬裁会同时改变明度和色相。

## 6. 对比度与可访问性

WCAG 2.2 是法规基线：

- 正文 4.5:1（AA）/ 7:1（AAA）
- 大字、粗体 3:1 / 4.5:1
- UI 部件、图形 3:1

公式：相对亮度 Y = 0.2126 R_lin + 0.7152 G_lin + 0.0722 B_lin，对比度 = (Y_浅 + 0.05) / (Y_深 + 0.05)。不四舍五入，4.499 不通过。

WCAG 对黄、橙、青偏乐观。脚本额外给出 APCA Lc 作为感知参考：正文大约 |Lc|≥60。黄字白底 WCAG 可能「过了」，APCA 会显示几乎看不见。

实践规则：

- 先派角色，再测正文 on-60、CTA 字 on-10、按钮块 vs 60。
- 不要把结构色原样当字色。从墨色池挑文字，浅底用长石灰、战舰灰、燕颔蓝；深底用鱼肚白、粉白、汉白玉。
- 黄、橙、浅朱在纸色上经常连 3:1 都没有，只能做装饰。
- 色盲：点缀与场不能只靠红绿区分。`cvd` 分项低于 0.5 时换点缀。
- 深色模式独立推导，不要整页反相。深底用燕颔蓝、豆沙、苷蓝绿，不用纯 `#000`；浅字用鱼肚白、粉白，不用纯 `#fff`。
- 朱红字配深底即使对比数字够，观感也发糊，避开。

## 7. 评分在看什么

`score_trio` 八项，权重在 `SCORE_WEIGHTS`：

| 分项 | 在惩罚什么 |
| --- | --- |
| chroma_hierarchy | 点缀既不比场艳、也不比场深浅分明；浅底高彩当了主场 |
| lightness_ladder | 主辅、主点明度贴在一起 |
| undertone | 主辅冷暖对撞（浓烈/市井/艳除外） |
| hue_relation | 主辅互补过冲、点缀没色相差、青间紫、非市井的红间绿 |
| contrast | 场上放不下正文、点缀贴在场上看不见 |
| cultural | 五行相克（近无彩的场不参与相克，否则甜白配青花会被误伤） |
| uniqueness | 三色 ΔE 过近，几乎是同一个色 |
| cvd | 红绿色盲下点缀消失 |

手选方案均分约 91。退化案例应显著低于此：三色同色 ~37，三色全是浅白 ~43，青间紫 ~63。

被脚本否决的方向如果用户可能想要，用一句话说明失败原因，不要暗中换色。

## 8. 变体：什么时候不用三色层级

| 变体 | 适用 |
| --- | --- |
| 主场更大、点缀更小 | 极简、编辑型、墨纸与文档 |
| 三色接近等权 | 三色需要平等对话（少用，容易散） |
| 单色阶度 | 墨分五色，废弃三切 |

不适用的场景：**等权**分类数据可视化（系列必须等权，否则颜色说谎）、语义色（成功/警告/错误不能因为 accent 额度用完而改色）、多品牌同屏、色浸。

仪表盘把系列色从 accent 里拆成第四套令牌。警告红不是品牌点缀。

注意这里说的只是**分类色**。序列色（同族明度阶）与双向色**不在拒绝范围内**——
它们本身就是不等权的，与「梅子青瓷同族三色靠明度分层」是同一套逻辑；图表的轴线、
网格、零线也正好由 `text` / `border` / `border_strong` 承接。完整边界与实测色梯见
`references/dataviz.md`。
