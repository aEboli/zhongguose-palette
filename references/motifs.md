# 纹样点缀

梅兰竹菊莲这类花卉、水墨风景、几何锦地，作为**点缀**加进设计里。

数据在 `references/motifs.json`，清单用 `palette.py motifs` 看。

## 第一条规矩：借色，不占色位

纹样不是第四个配比色。它**借用已有 token 的颜色**——资产里一个色值字符都没有，
不引入新 hex，也不让整体彩度负担上升。

一枝用 accent 色画的梅，它**就是**那 3%，不是额外加的一块红。

技术上只有三种借法，抗改坏能力依次递减：

| 写法 | 形态 | 评价 |
| --- | --- | --- |
| **mask（首选）** | 资产是不透明黑路径，只当 alpha 用；`background-color: var(--color-*)` 是唯一色彩入口 | 要引入新色必须在 CSS 里手打 hex，一条正则就能在 CI 里抓住 |
| currentColor | inline SVG，`fill="currentColor"`，靠 `color` 继承 | 可用，但要求 SVG 必须 inline |
| 裸 var() | `stroke="var(--color-border)"` | **不推荐**，见下 |

```css
.orn {
  --orn-ink: var(--color-border-strong);
  background-color: var(--orn-ink);
  -webkit-mask-image: var(--orn-tile);
          mask-image: var(--orn-tile);
  mask-mode: alpha;
  mask-repeat: repeat;
  mask-size: 160px 160px;
  opacity: .08;
}
```

**三条禁止**：

1. 不许在 data URI 里写 `fill`/`stroke` 的字面色值——那是库外 hex 的入口。
2. 不许用 `background-image` 承载有色纹样。`url()` 让 SVG 成为外部资源，
   `currentColor` 与 `var()` 在里面一律失效，想换色只能改那串 hex。
3. 裸 `var()` 写在 SVG 呈现属性上会**静默降级且方向相反**：`fill` 回落成纯黑
   （直接破「不许纯黑」那条），`stroke` 回落成 `none`（纹样凭空消失，无任何报错）。
   非要用就带 fallback：`stroke="var(--color-border, currentColor)"`。

## 两套账：墨量 vs 铺色面积

纹样的墨量与三色的 `pixel_pct` 是两件事，不能相加。

```
ink_pct = tile_coverage × patterned_share × layer_opacity × 100
```

`tile_coverage` 是单个瓦片按 alpha 加权积分得到的墨占比，资产生成时算好，
下游不必栅格化。这样 `ink_pct` 与 `pixel_pct` 同量纲，可以并排放进 `verify`。

**计费规则**：只有**彩度型借色**（C≥12，实际就是 accent / secondary）计费，
**中性借色**（surface / border / border_strong / text / muted）零计费。

理由是硬的：17 个 token 里只有 dominant / secondary / accent 有 `pixel_pct`，
而纹样最常借的 border / text 根本没有预算可扣。写「从 token 预算里扣」会留下未定义分支。

彩度型借色按折扣计费，不是 1:1 相减：

```
charge = ink_pct × (C_ink / C_accent)
charge ≤ 0.3 × accent_pct
```

1:1 会造假失败：水墨的 accent 额度只有 2.0%，一枚 opacity 0.06 的散点梅
`ink_pct≈0.10%`，扣掉无害；但锦地 `ink_pct 1.8%` 会吃掉 90% 的按钮额度，
而那层 0.06 的锦地在观感上根本不是第二块红。打折加上限之后水墨落到
`charge ≤ 0.6%`，正好放过线纹、挡住锦地与水墨渲染——后者必须改借中性色。

## alpha 上限（压在正文下时）

跨 6 个场景二分实测，保住正文对合成后底色仍 ≥4.5:1，取最小值：

| 借色 | alpha 上限 |
| --- | --- |
| surface | 1.00 |
| border | 1.00 |
| border_strong | 0.63 |
| muted | 0.50 |
| accent | 0.49 |
| secondary | 0.44 |
| text | 0.40 |

实用默认 **0.08**。

早先想把规则写成「压文字只能借 surface/border」，那是按实心填充（alpha=1.0）
测出来的结论。真实纹样带 opacity 0.04~0.12，在那个区间**每个 token 都过 4.5:1**
（连 text 在 0.20 都有 7.87:1）。所以闸门在 alpha 上，不在 token 白名单上。

线纹在 0.08 时 `ink_pct` 只有 0.08~0.71%，可读性闸门几乎永不咬人。
真正该管的是**噪声**：底纹越密越容易显脏，不是越容易读不清。

## 密纹想上高覆盖，必须配开光

`锦地开光` 是唯一允许 15~20% 覆盖率的构成——满地纹样上留出素白开窗写字。
它把可读性交给了**版式**而不是透明度，这正是「纹样不能压过文字」的传统解法。

不留素地就必然糊字。

## 成套：不可混、不可拆

| 套 | 成员 | 规矩 |
| --- | --- | --- |
| 四君子 | 折枝梅 丛兰 竹节竖列 折枝菊 | 四条屏语汇，一屏一种。把四种画进同一页面是错的 |
| 岁寒三友 | 折枝梅 竹节竖列 松枝 | 三件一组。梅与竹同框而无松，会被读成残缺的三友 |
| 三远 | 高远主峰 深远谷口 远山一线 | 可同页共存（那正是一幅山水的完整空间），但每种只许一处 |

用户说「梅兰竹菊」时提醒他这是四条屏，问要哪一种，或做成四个区块各一种。

## 季节

用错季节是最容易被识破的错。刚性分三档：

- **high**（会被立刻看出来）：荷 只属夏，冬季或岁末页面画荷即失手；菊 属秋
- **mid**：梅 属冬末早春
- **none**（四季可用）：竹、松、兰（作君子符号时读作无时令）、所有几何纹与风景纹

`palette.py ask` 会从话里读季节（春天/夏天/秋天/冬天/岁末/重阳…）。
high 硬说（「菊是秋的东西，你说的是春——这个错最容易被看出来」），
mid 软说（「梅本是冬末早春的花，不算硬错，但懂的人会觉得季节没对上」）。
mid 与 none 同路等于那一档白填——梅开盛夏正是最好认的那种错。

## 场景覆盖：不是每个场景都配齐了

「适配」按纹样自己的 `fits_scenes` 算，不是「没被 `avoid_scenes` 排除」。
后者会把年画场景下 12 条都说成适配，而其中 11 条的适配场景里根本没有年画。

实际分布（`palette.py motifs --scene <场景>` 的表头就是这个数）：

| 场景 | 真适配 | 可跨用 | 明确避开 |
| --- | --- | --- | --- |
| 宋瓷 | 18 | 6 | 4 |
| 水墨 / 江南 | 16 | 5–10 | 2–7 |
| 故宫 / 王府 | 10 | 18 | 0 |
| 青花 / 漆器 | 9 | 17–19 | 0–2 |
| 唐三彩 | 8 | 13 | 7 |
| 补服 | 6 | 21 | 1 |
| 敦煌 | 5 | 21 | 2 |
| 年画 / 祭天 | 4 | 14–23 | 1–10 |

这份表最初是按水墨/宋瓷的文人语汇建的，年画只 1 条、敦煌只 2 条。后来补了六条：
年画一路加**连年有余**（莲鱼谐音）、**牡丹团花**（团窠正圆）、**盘长结**；
敦煌一路加**藻井套叠**（窟顶方井）、**卷草纹**（北朝忍冬的唐代肥厚化）、
**联珠团窠**（萨珊系，经中亚传入）。年画 1→4、敦煌 2→5、唐三彩 3→8。

仍然欠配的：年画的门神、五毒、戏文人物，敦煌的飞天、供养人。这几样都是**人物**，
而人物不适合做 CSS mask 点缀——线密、要脸、缩到 100px 就成一团墨。它们属于插画，
不属于本技能的点缀层。祭天一路只 4 条也是同理：那套语汇的核心是建筑形制与礼器，
不是可平铺的纹。

跨场景借用不禁止，但 `motifs --scene` 会分两栏列，借来的那栏要向用户说明。

## 礼制禁忌

这些不是迷信，是这些图形在历史上承载过身份，用错会让人觉得不懂。
拒绝时要给替代路径，不要只说不行。

| 不用 | 为什么 | 改用 |
| --- | --- | --- |
| 五爪龙 | 元代起定为天子专用，明清严格限皇帝 | 夔纹（无角一足的龙形前身，不涉爪数），或卷草的抽象缠绕 |
| 四爪龙 | 清制贝勒、贝子的圆补用四爪龙，文献称「巨蟒」 | **蟒不是「小一号的龙」**——把五爪改四爪并未规避礼制，只是换了一级 |
| 龙凤对置 | 帝后配套形制 | 单用凤可以，成对是另一回事 |
| 十二章 | 十二种齐备，往下按九章/七章/五章/三章递减 | **任何「按等级解锁纹样数量」的设计都是在复刻章服制度** |
| 补子禽兽作用户等级 | 一品仙鹤、二品锦鸡…是清代官阶 | 单用一只鹤当徽章无碍；排成会员等第就是把官阶搬进产品 |
| 圆补/方补表示高低 | 清代宗室用圆补、文武官用方补，形状即身份 | 徽章取圆或方无碍，但不要让形状承担等级 |
| 大面积填金 | 元代庶人禁列直接列有「金黄」 | 金只走线不填面（与铁律 10 一致） |

## 反俗

水墨风景最容易做油的几处：

- **远山绝不做正弦或对称双峰**。要主峰偏在三分之一处、起伏不等高不等距、
  两端淡出、开口不闭合。做成对称波浪就是装饰性波纹，不是山。
- 一版只许一条远山。多画即成插画，不再是点缀。
- 不要满屏水墨背景图，不要渐变山。
- **云气带着墨为零**——它由上下两侧的墨边界反向定义。留白在中国画里是构成元素
  而不是背景，这一条把那个观念直接落成了可执行的东西，也是「点缀而非配比色」
  的最纯形态：0% 墨量，不可能变成第四色。

## 无障碍

纹样是装饰，不进无障碍树：`aria-hidden="true" focusable="false"`。

若纹样承载了信息（例如用图案区分类别），那它就不是装饰，必须另给文字或 `aria-label`。

- 纹样本身不该动。做了入场动画就在 `prefers-reduced-motion: reduce` 里去掉。
- `forced-colors: active` 时隐藏纹样——强制颜色模式会重置背景色，
  mask 方案会露出系统色块。

## 命令

```bash
python scripts/palette.py motifs                      # 全部纹样
python scripts/palette.py motifs --scene 水墨          # 只看适配某场景的
python scripts/palette.py motifs --category landscape  # flora / landscape / geometric

# ask 会自己认出纹样词，不用额外参数
python scripts/palette.py ask "茶室的网站，加一枝梅花点缀"

# 定妆时带上纹样，写进 handoff.json 的 ornament 段
python scripts/palette.py pick "鱼肚白+战舰灰+银朱" --scene 水墨 --media ui \
  --motif mei-zhezhi --motif yuanshan-yixian
```

## 交接

`handoff.json` 的 `ornament` 段。`frontend-design` 读它。

给的是「借哪个变量」而不是 hex——`borrows_var: "--color-border-strong"`。
段里那个 `borrowed_hex_for_reference` 只供人眼核对，不是渲染入口。

段内含：`prime_rule` `chosen` `suggestions` `render`（三种写法 + 三条禁止）
`alpha_ceilings` `ink_sources` `chroma_gate` `ink_ladder`
`budget`（含计费规则与当前 accent 额度）`sets` `taboo` `a11y` `issues`。

`chosen[]` 每条除了 `borrows_var` 还给 `borrows_alternates`（备选变量，
首选不可用时改指它）、`ink_pct` + `ink_range` + `ink_note`、`charge`（计费明细）。

**`issues[]` 必须念给用户听。** 借了白名单外的 token、彩度抬升超闸门、
alpha 超上限、场景气质不合、计费超额——都在这里。`pick` 会打印它。
静默交付一个不合规的纹样，症状是「这个纹样看起来有点重」，
而真正的原因在一个没人看的 JSON 字段里。

墨量口径：`ink_pct` 一律**按整版折算**，与 `pixel_pct` 同量纲。
框内/局部口径进 `ink_note`。踩过的坑：高远主峰原先写 `≤8`，那是框内占比，
与其余 21 条差一个数量级，于是计费闸门把一条正常纹样判成超额。

计费判据是**实测彩度 C≥12**，不是 token 名。年画的 surface 是荔肉白 C=13.2
要计费，水墨的 accent 是银灰 C=10.8 反倒不计。把 `surface` / `border` 当成
「中性」的同义词只在素净场景里偶然成立。
