# 改善配色一致性与可读性

## Why

用户反馈生成结果对比不清、缺少美感、颜色杂乱。现有 2224 项自检全部通过，但实际交付仍有三个可复现问题：

1. 色卡与 CSS 不一致：默认素雅方案的苋菜红按钮在 `apply_family_lock` 后变成白屈菜绿，按下状态又变成蜴蜊绿（黄褐色）。场景允许的破色没有贯穿交接与交互状态。
2. 对比只覆盖部分背景：青花浅色方案的说明文字在卡片上只有 4.04:1；宋瓷按钮悬停文字只有 4.04:1；默认浅色方案的输入轮廓在卡片上只有 2.57:1。
3. 技能要求照念脚本，前端交接又不要求读取完整文字配对；普通卡片被推荐铺满第二种彩色，容易把三色角色误用成三个视觉中心。

## What Changes

- 统一 `ask`、`generate`、`preview`、`pick` 使用的最终配色，保留用户选定的三色和场景允许的小面积破色。
- 派生面层、说明文字、轮廓、焦点及按钮状态时，同时约束真实背景上的对比度与颜色连续性；不能靠四舍五入把不合格值当合格。
- 默认素雅 UI 优先同族与中性色配合；普通内容卡片使用中性面层。高彩状态色只在实际状态中使用，第二种装饰色只占小面积。
- 技能从“照念结果”改为“审核后交付”；预览展示正文、说明、卡片、按钮状态与输入轮廓，供人工判断层次与配色。
- 补充针对上述失败的回归检查，更新相关说明，并按规范归档。

## Impact

- 主要涉及 `SKILL.md`、`scripts/engine.py`、`scripts/handoff.py`、`scripts/palette.py`、`scripts/selftest.py` 以及直接相关的参考文档。
- 这是生成结果与交接行为调整；现有命令和参数继续使用，526 色的原始色值保持原样。
- 工作开始时已有七个文件带未提交修改；实施时保留这些修改。
- 用户已确认完整提案，实施范围是当前仓库。已安装的技能副本需要单独同步。

## 验收

- 普通正文、说明和按钮文字在实际背景及交互状态上达到 4.5:1；必要轮廓与焦点相对相邻背景达到 3:1。装饰线条不强制 3:1。
- 同一方案在三色说明、预览、CSS、交接文件中颜色一致；按钮悬停和按下维持同一色相方向。
- 用默认素雅、青花、水墨、宋瓷、江南等浅深色样例验证；保留明确要求浓烈配色的场景。
- 通过现有回归、新增回归、技能结构检查和 OpenSpec 严格校验，并人工查看实际组件预览。
